# ADR-0012. Документация API из кода

| Поле | Значение |
|---|---|
| Статус | принято |
| Дата | 2026-11 |
| Этап | M10 (полировка и демонстрация) |
| Требования | FR-API-8, критерий 6 раздела 9 ТЗ; FR-DOC-101…137 ЧТЗ «Полировка и демонстрация» |
| Связанные документы | [Документация API](../api/README.md), [Архитектура](../01-Архитектура.md), [Ошибки API](../03-Доступ-и-роли.md), [ADR-0001](ADR-0001-стек.md), [ЧТЗ - Полировка и демонстрация](<../../.github/docs/Техническое задание/Полировка и демонстрация/ЧТЗ - Полировка и демонстрация.md>) |

## Контекст

К концу M9 в приложении 33 пути API, 19 API Resource и 15 FormRequest. FR-API-8 требует: «документация API генерируется из кода и проверяется на расхождения в CI». До M10 не было ни генератора, ни артефакта, ни проверки — документация жила в тексте `docs/*.md` и не обновлялась автоматически.

Ограничения:

- контракт API не меняется, схема базы не меняется;
- ручные аннотации в контроллерах не должны становиться источником схемы: они расходятся с кодом и не проверяются;
- ошибки API описаны в одном месте — `App\Http\Problem\ProblemRenderer` (RFC 9457, `application/problem+json`);
- проверка должна работать в CI без базы и сети;
- просмотр документации не должен быть доступен вне локальной среды.

## Решение

| № | Решение | Что означает |
|---|---|---|
| 1 | Генератор — `dedoc/scramble` v0.13 | Схема строится из маршрутов, правил FormRequest, полей API Resource и типов возврата. Ручных аннотаций для схемы не требуется |
| 2 | Пакет в `require`, а не в `require-dev` | Слой `vendor` в образе собирается с `--no-dev`; иначе страница документации не работала бы в контейнере, где идёт вся работа |
| 3 | Артефакт зафиксирован в репозитории: `docs/api/openapi.json` | Диф виден при ревью, проверить расхождение можно без запуска приложения |
| 4 | Проверка — сравнение сгенерированного документа с зафиксированным | `php artisan api:docs --check` в CI: расхождение делает сборку красной. Семантическое сравнение версий (breaking changes) не вводится |
| 5 | Единый формат ошибки — компонент `ProblemDetails` | Объявлен один раз; тело ошибочных ответов ссылается на него. Общие ответы пакета (`ValidationException`, `AuthorizationException`) переписываются на тот же формат |
| 6 | Ответы 401/404/409/422/429 и заголовок `Idempotency-Key` выводятся из фактов маршрута | Источник — middleware (`auth:sanctum`, `idempotency`, `throttle:`), параметры пути и наличие тела запроса. Новый маршрут получает корректное описание без правки документации |
| 7 | Статус `201` объявляется атрибутом `#[Response(201)]` на методе создания | Тип возврата даёт схему тела, но не код ответа; атрибут — единственная точечная аннотация, и он проверяется тестом |
| 8 | Просмотр `/docs/api` только в `local` и `testing` | Вне этих окружений маршрут не регистрируется (404), доступ дополнительно закрыт гейтом `viewApiDocs` |

## Последствия

Плюсы:

- схема отражает фактический код: поля ответа берутся из `toArray` ресурсов, правила запроса — из FormRequest;
- расхождение ловится в CI, а не на демонстрации;
- ошибки описаны одинаково на всех маршрутах, включая 403 у маршрутов с политикой;
- просмотр документации работает локально без отдельной сборки фронтенда.

Цена:

- зависимость в прод-слое (`dedoc/scramble` и `spatie/laravel-package-tools`);
- статический анализ не идеален: `@mixin` в PHPDoc ресурса связывает ресурс с моделью, без него появляется предупреждение и обобщённая схема;
- ответы, которые строит общий `ApiResponse::json()` (списки с `pagination`, составной блок `assignment + order`), описываются как объект без детализации полей;
- сравнение с зафиксированным файлом замечает любое изменение контракта, включая описания: артефакт обновляется вместе с кодом;
- requirements по breaking changes не проверяются автоматически: для сервиса это осознанное упрощение.

## Альтернативы и причины отказа

| Решение | Альтернатива | Почему отказались |
|---|---|---|
| Scramble | Ручной `openapi.yaml` | Расходится с кодом через неделю; проверка расхождения требует отдельного набора тестов на каждое поле |
| Scramble | `knuckleswtf/scribe` | Строит документацию вокруг аннотаций и примеров; схема ответов выводится хуже, а аннотации дублируют код |
| Scramble | Аннотации OpenAPI в контроллерах (`@OA\...`) | Дублирование контракта в двух местах; сгенерированная схема перестаёт быть следствием кода |
| Один атрибут `#[Response(201)]` | Правило «POST без параметра пути = 201» | Эвристика ошиблась бы на `POST /estimates` (200) и `POST /password/forgot` (202); атрибут проверяем и точечен |
| Сравнение с зафиксированным файлом | Семантическая проверка совместимости (oasdiff) | Дополнительный инструмент и порог «какие изменения считать ломающими»; для сервиса достаточно побайтового сравнения |
| Просмотр только в `local`/`testing` | Просмотр везде с basic-аутентификацией | Схема раскрывает все эндпоинты и коды; для стенда без внешнего доступа проще не регистрировать маршрут вообще |
