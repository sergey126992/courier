# ADR-0001. Стек приложения

| Поле | Значение |
|---|---|
| Статус | принято |
| Дата | 2026-11 |
| Этап | M0 (каркас) |
| Требования | FR-PLT-101…116, раздел 9.1 ЧТЗ «Основа и доступ» |
| Связанные документы | [Архитектура](../01-Архитектура.md), [Тесты](../14-Тесты.md), [README](../../README.md) |

## Контекст

Сервис городской курьерской службы: слоистая архитектура, очереди, три уровня тестов и непрерывная проверка выбраны под этот домен, а инструменты — как для промышленной эксплуатации, чтобы стек переносился на реальные проекты без переделки.

Ограничения, которые определили решения:

- на машине разработчика нет PHP и Composer — есть только Docker; значит всё, включая миграции и тесты, выполняется в контейнерах;

- одна и та же СУБД должна работать в разработке, тестах и CI, чтобы поведение не расходилось между средами;

- домен должен проверяться тестами без базы и без фреймворка;

- FR-PLT-101…116 фиксируют состав окружения: приложение, веб-сервер, PostgreSQL, Redis, обработчик очередей, планировщик, перехватчик почты.

## Решение

| Компонент | Версия | Роль |
|---|---|---|
| PHP | 8.3.36 (образ `php:8.3-fpm-alpine`) | язык приложения |
| Laravel | 12.71.0 | фреймворк, маршруты, консоль, очередь |
| Composer | 2.11.1 (образ `composer:2`) | зависимости PHP |
| PostgreSQL | 16 (`postgres:16-alpine`) | единственная СУБД для разработки, тестов и CI |
| Redis | 7 (`redis:7-alpine`) | кэш, сессии, очереди |
| predis | 3.7.1 | клиент Redis на чистом PHP, без расширения `redis` |
| Pest | 3.8.7 (+ `pest-plugin-laravel`, PHPUnit 11.5.56 как движок) | тесты трёх наборов |
| paratest | 7.8.6 | параллельный прогон Pest |
| PHPStan | 2.3.5 + Larastan 3.14.0, level 8 | статический анализ |
| Pint | из `laravel/pint`, пресет `laravel` | стиль кода |
| Node | 22 (`node:22-alpine`) | только сборка фронтенд-ассетов в образе |
| Scramble | принято, подключается на этапе M2 | генерация документации API из кода |

Окружение — в `docker-compose.yml`: сервисы `app`, `nginx`, `pgsql`, `redis`, `queue`, `scheduler`, `mailpit`. Точка входа разработчика — Docker Compose и команды `Makefile`.

## Альтернативы и причины отказа

| Решение | Альтернатива | Почему отказались |
|---|---|---|
| PostgreSQL 16 везде | SQLite в тестах | другой диалект: не проверяются реальные типы, ограничения целостности, поведение `jsonb`; план выполнения `EXPLAIN` не переносится; тест на SQLite не доказывает работоспособность на PostgreSQL |
| PostgreSQL 16 везде | MySQL/MariaDB | расхождения в типах, регистрозависимости, работе с JSON; домен доставки опирается на PostgreSQL-возможности (jsonb, ограничения), держать две СУБД в одном сервисе бессмысленно |
| Redis + predis | файловый кэш и очередь `database` | очередь и планировщик живут в отдельных контейнерах — нужен общий брокер; расширение `redis` потребовало бы отдельной сборки PHP, predis ставится composer-ом |
| Pest 3 | классические классы PHPUnit | Pest даёт датасеты (`->with([...])`), декларативные arch-тесты для границ слоёв и меньше шаблонного кода; PHPUnit остаётся движком внутри, отдельного выбора нет |
| PHPStan level 8 + Larastan | голый PHPStan | без Larastan анализатор не понимает фасады, Eloquent и контейнер Laravel — пришлось бы писать стабы и понижать уровень |
| Pint | PHP-CS-Fixer «с нуля» | Pint — тот же движок с готовым пресетом Laravel и проверкой одной командой `pint --test` |
| Docker Compose | локальные PHP/Composer на хосте | на хосте их нет; локальная установка противоречит требованию запуска без установки языка и СУБД |
| Docker Compose | Laravel Sail | нужны собственные сервисы (`queue`, `scheduler`, `mailpit`) и контроль над образом: непривилегированный пользователь, кэш слоёв, единая сборка ассетов |
| GitHub Actions + сервис `postgres:16` | тесты только локально | FR-PLT-109 требует проверки на чистом клоне с покрытием и порогом |

## Последствия и цена

Плюсы:

- одинаковое поведение СУБД в разработке, тестах и CI — ошибки диалекта не всплывают в продакшене;

- домен на чистом PHP тестируется без базы и без загрузки фреймворка, границы защищены arch-тестами;

- одна команда `make up` поднимает все сервисы, одна команда `make test` прогоняет все наборы;

- версии зафиксированы `composer.lock`, образы — тегами, окружение воспроизводимо.

Цена:

- первая сборка образа занимает минуты: `composer install` в слое зависимостей и `npm ci && npm run build` в слое ассетов;

- PostgreSQL в тестах — реальный сервис: `php artisan test` невозможен без контейнера с базой (в CI поднимается сервис `postgres`, хост подменяется на `127.0.0.1`);

- в тестах Redis подменяется драйверами `array`/`sync` (`phpunit.xml`): реальная очередь тестами M0 не проверяется — тесты каркаса не зависят от брокера;

- PHPStan уровня 8 требует аккуратных PHPDoc; для «магических» методов Pest и `TestCase` добавлены точечные `ignoreErrors`, а не понижение уровня;

- в dev-окружении сервисы запускаются с `user: "0:0"` из-за bind-mount в Docker Desktop на Windows (см. README); сам образ по умолчанию работает от пользователя `app`;

- LSP- и IDE-подсказки без локального PHP ограничены: автодополнение работает по исходникам в `vendor`, но запуск команд — только в контейнере.

## Что решение не покрывает

- Scramble подключён не будет до этапа M2 — сейчас в приложении нет API, документировать нечего.

- Выбор паттерна «Стратегия», идемпотентность, Outbox и транспорт событий фиксируются отдельными ADR на своих этапах.
