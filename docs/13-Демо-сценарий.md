# Демо-сценарий

Прогон на 5 минут без правок кода. Данные — в [Демо-данные](12-Демо-данные.md), правила — в [ЧТЗ - Полировка и демонстрация](<../.github/docs/Техническое задание/Полировка и демонстрация/ЧТЗ - Полировка и демонстрация.md>), запросы — в [courier.http](api/courier.http).

## Подготовка (до начала показа)

```sh
make up       # собрать и поднять окружение
make fresh    # пересоздать схему и налить демонстрационные данные
make demo     # учётные записи и ключевые номера
```

Проверить: `/up` — 200, Mailpit — на `http://127.0.0.1:8025`, `make demo` печатает учётные записи.

Переключения окружения — здесь: по ходу показа переменные не меняются, `make fresh` создал набор, даты привязаны к началу месяца.

Подготовка показа оповещений (M13) — тоже до начала:

```sh
docker compose up -d notifications-app notifications-worker notifications-scheduler
docker compose exec -T notifications-app php artisan notifications:check --json   # конфигурация и база
docker compose exec -T notifications-app php artisan notifications:metrics-snapshot --refresh --json
```

- Для шага DLQ задаются `NOTIFICATIONS_MAX_ATTEMPTS=1` (первый сбой сразу терминальный) и останавливается Mailpit: `docker compose stop mailpit`.
- Для шага транспорта поднимается профиль брокера: `docker compose --profile broker up -d rabbitmq`; смена `EVENTS_TRANSPORT` и `NOTIFICATIONS_TRANSPORT` — с пересозданием процессов (`docker compose up -d --force-recreate app queue scheduler notifications-app notifications-worker notifications-scheduler`).
- Сборщика метрик нет: `/metrics` читается напрямую (`http://127.0.0.1:8081/metrics`, сервисный токен), вкладка «Метрики» показывает тот же снимок.

## Шаги

| № | Время | Действие | Ожидаемый результат | Где смотреть |
|---|---|---|---|---|
| 1 | 40 с | Войти отправителем (`sender@courier.test` / `password`), открыть расчёт и посчитать один маршрут тремя транспортами | Три разных цены и ETA: меняется разбивка и ограничения по весу | `/cabinet/orders/create` либо `POST /api/v1/estimates` |
| 2 | 50 с | Создать заказ с ключом повтора, затем повторить тот же запрос | Второй заказ не создан, ответ совпадает с первым; повтор с другим телом даёт 422 | Кабинет отправителя, `POST /api/v1/orders` с `Idempotency-Key` |
| 3 | 40 с | Войти диспетчером (`dispatcher@courier.test`), открыть очередь | Видны заказы в разных статусах, включая созданные без курьера | `/dispatcher` |
| 4 | 50 с | Назначить курьера: сначала `nearest`, затем `best_eta` на другом заказе | Результат подбора меняется; в карточке заказа появляется назначение | Очередь `/dispatcher`, карточка `/dispatcher/orders/{order}` |
| 5 | 60 с | Войти курьером (`courier@courier.test`): смена уже открыта демо-набором; через API получить смену (`GET /api/v1/courier/shifts/current`), принять заказ, забрать и вручить (`POST /api/v1/assignments/{id}/accept`, `pickup`, `deliver`) | История статусов заполняется по шагам, в карточке видны метки времени | `GET /api/v1/courier/shifts/current`, карточка заказа |
| 6 | 30 с | Открыть публичный трекинг по коду из `make demo` | Статус, ETA и район без авторизации; адресов и персональных данных нет | `/tracking/{code}` |
| 7 | 30 с | Открыть Mailpit | Есть письма о смене статуса по выбранным каналам | `http://127.0.0.1:8025` |
| 8 | 50 с | Войти администратором (`admin@courier.test`), открыть отчёт и показать планы выполнения | Агрегаты по транспорту за текущий месяц; `EXPLAIN` до и после индекса | `GET /api/v1/reports/orders`, `docs/Производительность/` |
| 9 | 30 с | Прогнать тесты и проверку документации API | Тесты зелёные, описание API актуально | `make test`, `make docs-check` |

Итого — около 6 минут; при уверенном темпе — 5.

> **Курьер в вебе.** Веб-экрана курьера нет: смена и действия по заказу выполняются через API. В демо-наборе смена `courier@courier.test` уже открыта, поэтому шаг начинается с `GET /api/v1/courier/shifts/current`; приём, забор и вручение — `POST /api/v1/assignments/{id}/accept|pickup|deliver`.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Пустые экраны | `make fresh` — данные не налиты |
| 403 на экране | вошли другой ролью; `make demo` показывает, кто есть |
| Письма не приходят | проверить контейнер `queue` и Mailpit |
| Отчёт пустой | период по умолчанию — с начала месяца; данные привязаны к нему |
| `Описание API устарело` | `make docs` — контракт изменён после последней сборки |

## Чего в показе нет

- **SMS-канала** и мобильного клиента (device-токен — только служебный API); **переключение транспорта и провайдера из интерфейса** (страница только читает состояние); **мониторинг-стека** (сборщика Prometheus в `docker-compose.yml` нет, `/metrics` читается напрямую); **распределённой трассировки** (есть только `correlation_id`); **отдельного показа DLX** (сообщение возвращается в основной поток и разбирается общими правилами).
