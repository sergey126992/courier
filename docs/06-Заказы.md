# Заказы

Поведение этапа M4: создание с фиксацией цены, идемпотентность, отмена, список и карточка, история статусов. Требования — [ЧТЗ - География и заказы](<../.github/docs/Техническое задание/География и заказы/ЧТЗ - География и заказы.md>). Зоны — [05-Зоны-и-расстояния.md](05-Зоны-и-расстояния.md), цена и ETA — [04-Стоимость-и-ETA.md](04-Стоимость-и-ETA.md), диспетчеризация — [07-Диспетчеризация.md](07-Диспетчеризация.md), трекинг — [08-Трекинг.md](08-Трекинг.md), решения — [ADR-0003](adr/ADR-0003-идемпотентность.md), [ADR-0004](adr/ADR-0004-целостность-заказов.md).

## Жизненный цикл заказа

| Статус | Код | Название | Терминальный |
|---|---|---|---|
| created | `created` | Создан | нет |
| assigned | `assigned` | Назначен | нет |
| accepted | `accepted` | Принят | нет |
| picked_up | `picked_up` | Забран | нет |
| delivered | `delivered` | Вручён | нет |
| closed | `closed` | Закрыт | да |
| cancelled | `cancelled` | Отменён | да |
| failed | `failed` | Не выполнен | нет |

Заказ создаётся сразу в статусе «создан», черновика нет; «не выполнен» не терминален — заказ возвращается в «создан» для переназначения.

### Допустимые переходы

Правило — в домене `App\Domain\Order\OrderTransitions`; база хранит текущее значение и проверяет членство в наборе статусов.

| Из | В | Кто | Условие |
|---|---|---|---|
| создан | назначен | диспетчер | подбор или конкретный курьер |
| создан | отменён | отправитель, диспетчер | до забора |
| назначен | принят | курьер | своё назначение |
| назначен | отменён | отправитель, диспетчер | до забора |
| принят | забран | курьер | своё назначение |
| принят | отменён | отправитель, диспетчер | до забора |
| забран | вручён | курьер | своё назначение |
| забран | не выполнен | курьер | причина из закрытого перечня |
| забран | отменён | — | **запрещено** |
| вручён | закрыт | система или администратор | после вручения |
| не выполнен | создан | диспетчер | переназначение создаёт новую попытку |
| любой | любой иной | — | **запрещено** |

Переходы M5 меняют статус назначения вместе с заказом и пишут автора (диспетчер или курьер); отмена закрывает активное назначение в той же транзакции. Подробности — [07-Диспетчеризация.md](07-Диспетчеризация.md).

Недопустимый переход — 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED` с полем `status` и сообщением о текущем и целевом статусе; роль и автор — ответственность политики и операции.

## Создание заказа

`POST /api/v1/orders` — только подтверждённый отправитель; ключ `Idempotency-Key` обязателен.

| Поле | Обязательность | Правила |
|---|---|---|
| `transport` | обязательно | `on_foot`, `light`, `car` |
| `light_vehicle_kind` | обязательно для `light`, иначе запрещено | `bicycle`, `scooter`, `e_scooter`, `e_bike` |
| `pickup` | обязательно | `district`, `street`, `house`, `latitude`, `longitude`; лишние ключи отклоняются |
| `dropoff` | обязательно | те же поля, что у `pickup` |
| `parcel` | обязательно | вложенный объект: `weight_grams`, `dimensions{length,width,height}`, `declared_value{amount,currency}` (необязательно) |
| `requested_at` | необязательно | момент заявки; по умолчанию текущее время приложения; прошлое сверх допуска отклоняется |
| `is_paid_parking` | необязательно | признак платной парковки |
| `zone`, `zone_id` | запрещено | зону определяет сервер |

Порядок проверок:

1. формат полей — слой запроса (422 `VALIDATION_FAILED`);
2. адреса — `Address` и `Coordinates`: обязательные поля, диапазоны и точность координат;
3. зона по адресу забора — `ZoneResolver`; вне зон даёт 422 `ADDRESS_OUTSIDE_SERVICE_AREA` с полем `pickup`;
4. расстояние — провайдер `DistanceProvider`; сбой даёт 503 `DISTANCE_PROVIDER_UNAVAILABLE`;
5. расчёт цены и ETA по правилам M2 — пределы веса и радиуса дают свои коды 422;
6. транзакция записи: заказ, первая запись истории и событие `order.created` в таблице исходящих.

В заказе фиксируются и не пересчитываются: транспорт и вид лёгкого, расстояние, цена с валютой и разбивкой (включая нулевые строки), прогноз, адреса и посылка; смена тарифов цену не меняет.

Номер — последовательность `order_number_seq`, формат `CRG-ГГГГ-NNNNNN` (год текущей даты, шесть цифр). Код трекинга — случайные `trk_` и 16 hex-символов, без ПДн.

`requested_at` не может быть в прошлом: допуск на расхождение часов — 5 минут, значение настраивается `ORDERS_REQUESTED_AT_TOLERANCE_MINUTES`.

Лимит — 30 запросов в минуту на пользователя (`RATE_LIMIT_ORDERS_CREATE_ATTEMPTS`, `RATE_LIMIT_ORDERS_CREATE_DECAY`), превышение — 429 `RATE_LIMITED` с `Retry-After`; чтение не лимитируется.

Ответ 201 с заголовком `Location: /api/v1/orders/{id}`. Пример фактического ответа:

```json
{
  "data": {
    "number": "CRG-2026-000001",
    "tracking_code": "trk_cd96ad16ef547f62",
    "status": "created",
    "transport": "light",
    "light_vehicle_kind": "bicycle",
    "distance_km": 1.8,
    "eta_minutes": 15,
    "price": { "amount": 19400, "currency": "RUB" },
    "breakdown": [
      { "code": "base", "label": "Базовая ставка", "amount": 14900 },
      { "code": "distance", "label": "1.8 км", "amount": 4500 },
      { "code": "surge", "label": "Надбавка за час пик", "amount": 0 }
    ],
    "pickup": { "district": "Тверской", "street": "Тверская", "house": "7" },
    "dropoff": { "district": "Тверской", "street": "Тверская", "house": "9" },
    "created_at": "2026-11-04T20:15:00+03:00"
  }
}
```

Коды ответа:

| Код | Когда | `code` в теле |
|---|---|---|
| 201 | заказ создан | — |
| 401 | нет токена | `INVALID_CREDENTIALS` |
| 403 | почта не подтверждена / роль без права | `EMAIL_NOT_VERIFIED` / `FORBIDDEN` |
| 409 | параллельный запрос с тем же ключом | `IDEMPOTENCY_KEY_IN_PROGRESS` |
| 422 | формат полей, зона, расчёт, конфликт ключа | `VALIDATION_FAILED`, `ADDRESS_OUTSIDE_SERVICE_AREA`, коды расчёта, `IDEMPOTENCY_KEY_CONFLICT` |
| 429 | превышен лимит | `RATE_LIMITED` + `Retry-After` |
| 503 | провайдер расстояний недоступен | `DISTANCE_PROVIDER_UNAVAILABLE` |

## Идемпотентность создания

Ключ повтора обрабатывает `App\Http\Middleware\EnsureIdempotencyKey` **до** операции: повтор получает сохранённый ответ без выполнения действия.

| Правило | Поведение |
|---|---|
| Заголовок | `Idempotency-Key`, 16–64 символа; отсутствие или неверная длина — 422 `VALIDATION_FAILED` с полем `Idempotency-Key` |
| Область уникальности | пара `(user_id, key)`: один и тот же ключ у разных пользователей — разные заказы |
| Отпечаток тела | SHA-256 канонического JSON: порядок ключей не влияет, повтор с переставленными полями — тот же запрос |
| Повтор с тем же телом | сохранённый ответ и тот же код (201), второй заказ не создаётся |
| Повтор с другим телом | 422 `IDEMPOTENCY_KEY_CONFLICT` |
| Одновременный повтор | 409 `IDEMPOTENCY_KEY_IN_PROGRESS`: запись занята, ответа ещё нет |
| Неудачный запрос | запись ключа удаляется, повтор с тем же заголовком разрешён |
| Срок хранения | 24 часа (`ORDERS_IDEMPOTENCY_TTL_HOURS`); просроченная запись считается отсутствующей и удаляется |
| Очистка | `php artisan orders:purge-idempotency-keys`, по расписанию — каждый час |

Повтор не отдаёт `Location`: сохранены только тело и код, адрес созданного заказа есть лишь в первом ответе.

Таблица `idempotency_keys`: `user_id`, `key` (уникальный в паре с пользователем), `request_hash`, `status` (`in_progress`/`completed`), `response_code`, `response_body` (jsonb), `expires_at`; уникальный индекс `(user_id, key)`, индекс по `expires_at` для очистки.

## Отмена заказа

`POST /api/v1/orders/{order}/cancel`, необязательное поле `reason` (до 255 символов) попадает в историю.

- Отправитель отменяет свой заказ, диспетчер — любой, без согласия; автор перехода различается в истории.
- Отмена только до забора: после — 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED` с полем `status`.
- Повторная отмена уже отменённого заказа — тоже 409.
- Чужой заказ для отправителя и заказ, недоступный роли, — 404: существование записи не раскрывается.
- Заполняется `cancelled_at`, статус меняется доменным методом, в историю пишется автор и причина.
- Активное назначение закрывается в той же транзакции статусом «отменено», смена курьера остаётся открытой.
- Ответ 200 — карточка заказа в краткой форме с новым статусом.

## Чтение заказов

### Список: `GET /api/v1/orders`

| Параметр | Правила |
|---|---|
| `status[]` | одно или несколько значений статуса из набора |
| `from`, `to` | период по времени создания; `to` не раньше `from` |
| `sort` | только `created_at` или `-created_at` (по умолчанию `-created_at`, новые сверху) |
| `limit` | 1–100, по умолчанию 20 |
| `cursor` | курсор предыдущей страницы |

Недопустимые фильтры, статусы и сортировка — 422. Порядок устойчивый: время создания и идентификатор вторым ключом, без дублей и пропусков между страницами.

Ответ 200 — краткие записи и блок пагинации:

```json
{
  "data": [
    {
      "number": "CRG-2026-000001",
      "tracking_code": "trk_cd96ad16ef547f62",
      "status": "created",
      "transport": "light",
      "light_vehicle_kind": "bicycle",
      "distance_km": 1.8,
      "eta_minutes": 15,
      "price": { "amount": 19400, "currency": "RUB" },
      "created_at": "2026-11-04T20:15:00+03:00"
    }
  ],
  "pagination": {
    "per_page": 1,
    "has_more": true,
    "next": "http://127.0.0.1:8080/api/v1/orders?cursor=...",
    "prev": null
  }
}
```

`next` и `prev` — готовые ссылки или `null`, если страницы нет.

### Карточка: `GET /api/v1/orders/{order}`

Ответ 200: `number`, `tracking_code`, `status`, `transport`, `light_vehicle_kind`, `distance_km`, `eta_minutes`, `price`, `breakdown`, `parcel`, `pickup` и `dropoff` (с координатами), `requested_at`, `cancelled_at`, `created_at`, `history`; история и авторы загружаются заранее.

## История статусов

`order_status_history` — только добавление: `from_status` (`null` у первой), `to_status`, `changed_by` (`null` для системного), `reason`, `created_at`; `updated_at` нет.

Изменение и удаление запрещены в модели: `App\Models\Order\OrderStatusHistory` переопределяет `save()`/`delete()` и бросает `StatusHistoryIsImmutable`; удаление — каскадом только с заказом.

Переход пишется одной записью в той же транзакции; первая — `null → created` с автором-отправителем.

## Права

| Роль | Список | Карточка | Создание | Отмена |
|---|---|---|---|---|
| Отправитель | свои заказы | свой заказ | да, после подтверждения почты | свой заказ до забора |
| Диспетчер | все заказы | любой заказ | нет | любой заказ до забора |
| Курьер | 403 | 403 | 403 | 404 |
| Администратор | 403 | 403 | 403 | 404 |
| Гость | 401 | 401 | 401 | 401 |

Чужой заказ для отправителя — 404, неотличим от несуществующего. Курьер и администратор заказы не читают: операционные данные курьер берёт из `GET /api/v1/assignments`.

## Дальнейшая судьба заказа

- Смены, назначение, принятие, забор, вручение и неудача — маршруты M5 ([07-Диспетчеризация.md](07-Диспетчеризация.md)); каждый переход пишется в историю с автором, а назначение, забор, вручение и неудача — ещё и событие в `outbox_messages`.
- Геоточки, последняя позиция и публичный трекинг по `tracking_code` — M6 ([08-Трекинг.md](08-Трекинг.md)).
- События публикует `outbox:publish`, уведомления — слушатель M7 ([09-Асинхронность.md](09-Асинхронность.md)).
