# Диспетчеризация

Смены, доступность и фильтры, три правила подбора, назначение и переназначение, действия курьера, карточка и список. Требования — [ЧТЗ - Диспетчеризация и трекинг](<../.github/docs/Техническое задание/Диспетчеризация и трекинг/ЧТЗ - Диспетчеризация и трекинг.md>); трекинг — [08-Трекинг.md](08-Трекинг.md), таблицы — [02-Схема-данных.md](02-Схема-данных.md), решения — [ADR-0005](adr/ADR-0005-стратегии-подбора.md), [ADR-0006](adr/ADR-0006-целостность-диспетчеризации.md).

## Смена курьера

Отдельного статуса нет: смена открыта, пока не заполнено `ended_at`; `status` (`open`/`closed`) и `is_open` вычисляются из данных.

`POST /api/v1/courier/shifts` — тело необязательное:

| Поле | Правила |
|---|---|
| `zone_id` | необязательно, `null` или идентификатор существующей зоны; смена без зоны подходит для заказов любой зоны |
| `courier_id`, `started_at`, `ended_at` | запрещены: их определяет сервер |

Ответ 201 — смена: `id`, `courier_id`, `zone_id`, `started_at`, `ended_at`, `status`, `is_open`.

| Правило открытия | Поведение |
|---|---|
| Профиль курьера | без профиля — 403 `FORBIDDEN`; `is_active = false` — 409 `COURIER_INACTIVE` |
| Одна открытая смена | повторное открытие — 409 `COURIER_SHIFT_ALREADY_OPEN` |
| Пересечение интервалов | открытая смена считается бесконечной; нарушение — 409 `COURIER_SHIFT_OVERLAP` |
| Гонка запросов | то же ограничение в базе (`EXCLUDE USING gist`) переводится в те же коды, а не в 500 |

Смежные смены «20:00–21:00» и «21:00–22:00» допустимы: конец не пересекается с началом.

`GET /api/v1/courier/shifts/current` — открытая смена вызывающего курьера (последняя по времени начала); нет смены — 404 `NOT_FOUND`, другая роль — 403 `FORBIDDEN`.

`POST /api/v1/courier/shifts/{shift}/close` — окончание ставит сервер, строка блокируется на время транзакции; чужая смена — 404, другая роль — 403. Отказы:

| Условие | Код |
|---|---|
| смена уже закрыта | 409 `COURIER_SHIFT_NOT_OPEN` |
| у курьера есть активное назначение (назначено, принято, забрано) | 409 `SHIFT_HAS_ACTIVE_ASSIGNMENT` |
| окончание не позже начала | 422 `VALIDATION_FAILED`, поле `ended_at` |

Активность назначения проверяется по курьеру, а не по смене (назначение к смене не привязано). Отмена заказа снимает активное назначение, но смену не закрывает.

## Доступность и фильтры кандидатов

Кандидаты отбираются одним запросом с соединениями; жёсткие фильтры — условия отбора, а не ранжирование.

| Фильтр | Условие |
|---|---|
| роль | `users.role = courier` |
| профиль | `courier_profiles.is_active = true` |
| смена | есть открытая смена (`ended_at IS NULL`) |
| зона | зона смены пуста или совпадает с зоной заказа |
| транспорт | `courier_profiles.transport_type` совпадает с транспортом заказа |
| занятость | нет назначения в статусе `assigned`, `accepted`, `picked_up` |
| посылка | вес не больше предела транспорта и расстояние заказа не больше радиуса транспорта |

Посылка проверяется один раз по параметрам транспорта заказа: транспорт курьера совпадает с заказом, пределы общие. Неподходящая посылка даёт пустой список (`NO_COURIER_AVAILABLE` при назначении).

Метрики: `distance_to_pickup_km` — расстояние от последней позиции до забора; `pickup_approach_minutes` — оно же, делённое на скорость транспорта с учётом часа пик, вверх до минуты; `assignments_in_shift` — назначений с начала смены.

Деградация: без позиции, при недоступном провайдере или некорректных координатах кандидат остаётся в списке без расстояния и времени подхода, получает худший ранг; код ответа не меняется.

`GET /api/v1/orders/{order}/candidates` — заказ обязан быть «создан», иначе 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED`; необязательный `strategy` (неизвестное — 422 `VALIDATION_FAILED`). Лимит `dispatch.candidates_limit` (`DISPATCH_CANDIDATES_LIMIT`, по умолчанию 20) — после упорядочивания.

Ответ: `data[]` — `id`, `name`, `transport`, `light_vehicle_kind`, `distance_to_pickup_km`, `assignments_in_shift`, `pickup_approach_minutes`; `meta` — `strategy` (применённое правило) и `order_eta_minutes` (прогноз для «лучший ETA»).

## Правила подбора

Правило только упорядочивает набор; победитель — первый элемент.

| Правило | `strategy` | Метрика (меньше — лучше) |
|---|---|---|
| Ближайший | `nearest` | расстояние до точки забора |
| Наименее загруженный | `least_loaded` | число назначений за смену |
| Лучший ETA | `best_eta` | время подхода к забору + зафиксированный прогноз заказа |

Ничьи разрешаются одинаково: метрика, затем число назначений за смену, затем идентификатор курьера; кандидат с неопределимой метрикой — в конце. Порядок не зависит от исходного порядка набора.

Правило — из `strategy`, иначе из `dispatch.strategy` (`DISPATCH_STRATEGY`, по умолчанию `nearest`); неизвестное в конфигурации — ошибка `UnknownAssignmentStrategy`, в запросе отсекает валидация. Набор — тег `dispatch.assignment-strategies` в `AppServiceProvider`: новое правило — класс, случай перечисления и строка списка.

## Назначение и переназначение

`POST /api/v1/orders/{order}/assign` — тело необязательное: `courier_id` (без него — автоматический подбор) и `strategy` (`nearest`, `least_loaded`, `best_eta`; без него — значение конфигурации).

В одной транзакции: блокировка заказа → статус «создан», иначе 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED` → выбор правила и кандидата (первый по правилу или вручную) → запись назначения («назначено», правило, расстояние до забора) → переход «создан → назначен» с историей → событие `order.assigned` в исходящих.

| Условие отказа | Код |
|---|---|
| нет кандидатов при автоматическом подборе | 409 `NO_COURIER_AVAILABLE`, заказ остаётся «создан» |
| указан не курьер, нет профиля, профиль неактивен, нет открытой смены, есть активное назначение | 409 `COURIER_NOT_AVAILABLE` |
| транспорт курьера не совпадает с заказом | 422 `COURIER_TRANSPORT_MISMATCH`, поле `courier_id` |
| зона смены не совпадает с зоной заказа | 422 `COURIER_ZONE_MISMATCH`, поле `courier_id` |
| курьер не проходит по весу или радиусу посылки | 409 `COURIER_NOT_AVAILABLE` |
| параллельный запрос уже создал активное назначение заказа или курьера | 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED` |

Ручное назначение проверяется так же: недоступность (409), транспорт и зона (422), затем список кандидатов с весом и радиусом. Гонку отсекают блокировка заказа и частичные уникальные индексы.

Ответ 200 — назначение и краткий блок заказа:
 Ответ 200 — `assignment` (`id`, `status`, `status_label`, `strategy`, `distance_to_pickup_km`, `assigned_at`, `accepted_at`, `picked_up_at`, `delivered_at`, `failed_at`, `failure_reason`, `failure_comment`, `courier` — `id`, `name`, `transport`, `light_vehicle_kind`) и краткий `order` (`number`, `status`, `status_label`).

`POST /api/v1/orders/{order}/reassign` — новая попытка: заказ обязан быть «не выполнен», иначе 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED`. Переход «не выполнен → создан» пишется отдельной записью истории, в той же транзакции — обычное назначение; прежняя строка остаётся со статусом «не выполнено» и причиной.

Отмена заказа закрывает активное назначение в той же транзакции (`assigned → cancelled`, `accepted → cancelled`), смена остаётся открытой; после забора отмена запрещена доменным переходом заказа.

## Действия курьера

| Действие | Переход назначения | Переход заказа |
|---|---|---|
| `accept` | назначено → принято | назначен → принят |
| `pickup` | принято → забрано | принят → забран |
| `deliver` | забрано → вручено | забран → вручён |
| `fail` | забрано → не выполнено | забран → не выполнен |

Тело `accept`, `pickup` и `deliver` не требуется. `fail` принимает:

| Поле | Правила |
|---|---|
| `reason` | обязательно, только `recipient_unavailable`, `recipient_refused`, `wrong_address`, `access_denied`, `other` |
| `comment` | необязательно, строка до 500 символов |

Порядок: блокировка назначения → терминальное назначение даёт 409 `ASSIGNMENT_NOT_ACTIVE` → блокировка заказа → переход заказа → переход назначения → история с автором-курьером. У `fail` причина и комментарий остаются в назначении, код причины — в `reason` истории.

- Повтор выполненного действия даёт 409 `ORDER_STATUS_TRANSITION_NOT_ALLOWED` без второй записи истории; действие по терминальному назначению отсекается раньше кодом `ASSIGNMENT_NOT_ACTIVE`.
- Чужое назначение неотличимо от несуществующего (404), другая роль — 403.
- `order.picked_up`, `order.delivered` и `order.failed` пишутся в той же транзакции; `accept` события не пишет.

Ответ 200 — карточка назначения и краткий блок заказа (обёртка как у назначения).

## Карточка и список назначений

`GET /api/v1/assignments/{assignment}` — полная карточка для курьера-владельца и диспетчера; отправитель и администратор — 403, чужое назначение курьеру — 404.

| Поле | Содержание |
|---|---|
| `id`, `status`, `status_label` | идентификатор, код и подпись статуса |
| `strategy` | фактически применённое правило подбора |
| `distance_to_pickup_km` | расстояние до забора на момент назначения |
| `assigned_at`, `accepted_at`, `picked_up_at`, `delivered_at`, `failed_at` | время этапов; непройденный — `null` |
| `failure_reason`, `failure_comment` | причина и комментарий неудачи; вне неудачи — `null` |
| `courier` | `id`, `name`, `transport`, `light_vehicle_kind` |
| `order` | `number`, `status`, `status_label`, `pickup` и `dropoff` (район, улица, дом), `parcel.weight_grams`, `price`, `eta_minutes`, `requested_at` |

Адреса отдаются без координат — только район, улица и дом. Связи курьера, профиля и заказа загружаются заранее, карточка не порождает лишних запросов.

`GET /api/v1/assignments` — назначения курьера (другая роль — 403); `limit` — 1–100, по умолчанию 20, `cursor`. Порядок: активное первым, затем история по времени и идентификатору. Краткая запись: `id`, `status`, `status_label`, `order.number`, `order.status`, `order.status_label`, `pickup.district`, `dropoff.district`, `assigned_at`; `pagination` (`per_page`, `has_more`, `next`, `prev`).

## Статусы назначения

| Статус | Код | Подпись | Активный |
|---|---|---|---|
| назначено | `assigned` | Назначено | да |
| принято | `accepted` | Принято | да |
| забрано | `picked_up` | Забрано | да |
| вручено | `delivered` | Вручено | нет |
| не выполнено | `failed` | Не выполнено | нет |
| отменено | `cancelled` | Отменено | нет |

Терминальных переходов нет: продолжение — новая попытка. У заказа и курьера одновременно одна активная строка.

## Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `COURIER_INACTIVE` | 409 | профиль курьера неактивен |
| `COURIER_SHIFT_ALREADY_OPEN` | 409 | у курьера уже есть открытая смена |
| `COURIER_SHIFT_OVERLAP` | 409 | новая смена пересекается с существующей |
| `COURIER_SHIFT_NOT_OPEN` | 409 | смена не открыта или уже закрыта |
| `SHIFT_HAS_ACTIVE_ASSIGNMENT` | 409 | закрытие смены при активном назначении |
| `COURIER_NOT_AVAILABLE` | 409 | указанный курьер недоступен или не проходит по посылке |
| `NO_COURIER_AVAILABLE` | 409 | подбор не нашёл кандидатов |
| `COURIER_TRANSPORT_MISMATCH` | 422 | транспорт курьера не совпадает с заказом |
| `COURIER_ZONE_MISMATCH` | 422 | зона смены курьера не совпадает с зоной заказа |
| `ASSIGNMENT_NOT_ACTIVE` | 409 | действие по терминальному назначению |
| `ORDER_STATUS_TRANSITION_NOT_ALLOWED` | 409 | статус заказа не допускает действие или гонка назначений |
| `VALIDATION_FAILED` | 422 | формат полей, неизвестное правило, некорректный период смены |
| `FORBIDDEN` | 403 | роль без права или курьер без профиля |
| `NOT_FOUND` | 404 | чужой или несуществующий ресурс |

Детали — в `errors` (`field`, `message`), тексты — в `lang/ru/errors.php`, `lang/ru/dispatch.php`, `lang/ru/orders.php`.

## Лимиты частоты

| Маршрут | Именованный лимит | Ключ | По умолчанию |
|---|---|---|---|
| открытие смены, действия курьера | `courier-actions` | курьер | 60 запросов в минуту |
| кандидаты, назначение, переназначение | `dispatch-assign` | диспетчер | 30 запросов в минуту |

Значения — в `config/rate_limits.php` (`RATE_LIMIT_COURIER_ACTIONS_*`, `RATE_LIMIT_DISPATCH_ASSIGN_*`). Превышение — 429 `RATE_LIMITED` с `Retry-After`; чтение смены, списка и карточки не ограничено.
