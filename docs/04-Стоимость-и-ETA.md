# Расчёт стоимости и ETA

Предварительный расчёт цены и прогноза доставки для трёх типов транспорта (этап M2). Требования — в [ЧТЗ - Расчёт стоимости и ETA](<../.github/docs/Техническое задание/Расчёт стоимости и ETA/ЧТЗ - Расчёт стоимости и ETA.md>); слои — в [01-Архитектура.md](01-Архитектура.md), обоснование схемы — в [ADR-0002](adr/ADR-0002-стратегия-расчёта.md).

## Как устроен расчёт

Поток: `EstimateDeliveryRequest` (проверка состава и формата полей) → `EstimateDelivery` (сборка `EstimateInput`, перевод доменных исключений в коды API) → `StrategyDeliveryEstimator` (первая стратегия с `supports() === true`: `OnFootEstimateStrategy`, `LightTransportEstimateStrategy`, `CarEstimateStrategy`) → `EstimateCalculator` (общая арифметика и проверка пределов) → `PriceQuote` (проверка «сумма строк = итог») → `EstimateResource` (JSON без обёртки `data`).

- Тип транспорта определяет стратегию: карта `TransportType::value => класс` живёт в `AppServiceProvider`, компонент выбора получает готовый набор.
- Стратегия передаёт калькулятору параметры своего транспорта и применимые надбавки; своей арифметики у неё нет.
- Параметры приходят из `PricingConfig` — единственного места, где `config/pricing.php` превращается в `TransportParams`, `PeakHourSchedule` и `Money`. Домен конфигурацию не читает.

Арифметика (`EstimateCalculator`):

- `total = base + rate_per_km × distance + Σ надбавок`;
- процентная надбавка — от `base + distance`, фиксированная прибавляется как есть;
- `eta_minutes = ceil(distance ÷ скорость × 60) + время на операции`; скорость — с учётом вида лёгкого транспорта и часа пик.

Проверки идут до арифметики: вес больше предела и расстояние больше радиуса обслуживания отклоняются доменными исключениями. Расстояние, равное пределу, допустимо.

## Правила по транспорту

Значения по умолчанию — из `config/pricing.php`; каждый параметр переопределяется `PRICING_*`, поэтому тариф меняется настройкой, а не правкой стратегии.

| Транспорт | `transport` | Предельный вес | Радиус | Базовая ставка | Ставка за км | Скорость | Надбавка за час пик | Парковка | Время на операции |
|---|---|---|---|---|---|---|---|---|---|
| Пеший | `on_foot` | 3000 г | 2 км | 99 ₽ | 20 ₽ | 4.5 км/ч | нет | нет | 10 мин |
| Лёгкий | `light` | 15000 г | 7 км | 149 ₽ | 25 ₽ | по виду транспорта | 10% | нет | 7 мин |
| Автомобиль | `car` | 100000 г | 20 км | 249 ₽ | 35 ₽ | 25 км/ч (18 км/ч в час пик) | 15% | 50 ₽ | 5 мин |

Скорости лёгкого транспорта: `bicycle` — 15 км/ч, `scooter` — 12 км/ч, `e_scooter` — 18 км/ч, `e_bike` — 20 км/ч. Надбавка за час пик у лёгкого есть только у `scooter` и `e_scooter`; у велосипеда и электровелосипеда строка `surge` нулевая. Скорость лёгкого от часа пик не зависит — поправка только у автомобиля.

Часы пик — 07:00–10:00 и 17:00–20:00, границы включаются; время — в `config('app.timezone')`.

## Деньги

- Сумма — целое число минорных единиц (копеек), валюта — отдельным полем; чисел с плавающей точкой нет.
- `Money` неизменяем: сложение, вычитание и умножение возвращают новый объект.
- Округление при умножении на коэффициент — «половина вверх», симметрично и для отрицательных сумм.
- Сложение, вычитание и сравнение сумм в разных валютах запрещены: `CurrencyMismatch`.
- Форматирование (`format()`) отделено от расчёта; в API отдаются минорные единицы и код валюты.

## Разбивка

Коды строк заданы перечислением `BreakdownCode`:

| Код | Название по умолчанию | Когда присутствует |
|---|---|---|
| `base` | Базовая ставка | всегда |
| `distance` | Расстояние (подпись — `«1.8 км»`) | всегда |
| `surge` | Надбавка за час пик | всегда у `light` и `car`; вне часа пик нулевая |
| `parking` | Надбавка за парковку | только у `car` при `is_paid_parking = true` |

Правила:

- сумма `amount` всех строк равна `price.amount`; расхождение — дефект, отклоняется в `PriceQuote` (`BreakdownMismatch`);
- нулевые строки сохраняются, чтобы клиент видел структуру цены: у лёгкого и авто `surge` есть всегда, `parking` — только у авто с платной парковкой;
- у пешего транспорта разбивка состоит только из `base` и `distance`.

## API: `POST /api/v1/estimates`

| Параметр | Значение |
|---|---|
| Маршрут | `POST /api/v1/estimates`, имя `estimates.store` |
| Middleware | `auth:sanctum`, `verified.api`, `throttle:pricing-estimate` |
| Доступ | подтверждённый отправитель: право `estimate-delivery` (`role->canCreateOrders()`) |
| Формат ответа | плоский JSON, обёртки `data` нет |

Лимит `pricing-estimate` — 60 запросов за 60 секунд, ключ — идентификатор пользователя (для неаутентифицированного — IP); настраивается в `config/rate_limits.php` (`RATE_LIMIT_ESTIMATE_ATTEMPTS`, `RATE_LIMIT_ESTIMATE_DECAY`). При превышении — 429 и `Retry-After`.

Входные поля:

| Поле | Обязательность | Правила |
|---|---|---|
| `transport` | обязательно | `on_foot`, `light` или `car` |
| `light_vehicle_kind` | обязательно для `light`, иначе запрещено | `bicycle`, `scooter`, `e_scooter`, `e_bike` |
| `distance_km` | обязательно | число больше нуля, не более двух знаков после запятой |
| `weight_grams` | обязательно | целое больше нуля |
| `dimensions` | обязательно | объект `{length, width, height}`, каждое значение — целое больше нуля, сантиметры |
| `declared_value` | необязательно | объект `{amount, currency}`; `amount` — целое в минорных единицах, `currency` — трёхбуквенный код |
| `requested_at` | необязательно | момент заявки в ISO 8601; по умолчанию текущее время приложения |
| `is_paid_parking` | необязательно | логическое, по умолчанию `false` |

Ответ 200:

```json
{
  "transport": "on_foot",
  "light_vehicle_kind": null,
  "distance_km": 1.8,
  "eta_minutes": 34,
  "price": { "amount": 13500, "currency": "RUB" },
  "breakdown": [
    { "code": "base", "label": "Базовая ставка", "amount": 9900 },
    { "code": "distance", "label": "1.8 км", "amount": 3600 }
  ]
}
```

Фактические результаты на маршруте 1.8 км и весе 1.5 кг (заявка вне часа пик):

| Транспорт | `eta_minutes` | `price.amount` | Строки разбивки |
|---|---|---|---|
| `on_foot` | 34 | 13500 | `base` 9900 + `distance` 3600 |
| `light`, `e_bike` | 13 | 19400 | `base` 14900 + `distance` 4500 + `surge` 0 |
| `car`, платная парковка | 10 | 36200 | `base` 24900 + `distance` 6300 + `surge` 0 + `parking` 5000 |

Коды ответа:

| Код | Когда | `code` в теле |
|---|---|---|
| 200 | расчёт выполнен | — |
| 401 | нет токена | `INVALID_CREDENTIALS` |
| 403 | почта не подтверждена / роль без права | `EMAIL_NOT_VERIFIED` / `FORBIDDEN` |
| 422 | ошибка формата полей или доменное ограничение расчёта | `VALIDATION_FAILED` или код из раздела ниже |
| 429 | превышен лимит | `RATE_LIMITED` + `Retry-After` |

## Коды ошибок расчёта

| Код | HTTP | Причина | `details[0].field` |
|---|---|---|---|
| `PARCEL_TOO_HEAVY_FOR_TRANSPORT` | 422 | вес больше предела транспорта | `parcel.weight_grams` |
| `PARCEL_OUTSIDE_DELIVERY_RADIUS` | 422 | расстояние больше радиуса обслуживания | `distance_km` |
| `UNSUPPORTED_TRANSPORT` | 422 | ни одна стратегия не поддержала входные данные | `transport` |

В деталях всегда есть предел и название типа транспорта: для радиуса — «максимум 20 км для транспорта „Автомобиль“», для неподдерживаемого типа — перечень допустимых значений. Тексты — в `lang/ru/pricing.php`, коды и статусы — в `ErrorCode`.

## Как добавить новый тип транспорта

1. Класс стратегии в `app/Domain/Pricing/Strategies`, реализующий `DeliveryEstimateStrategy` (`supports()`, `estimate()`); свою арифметику не пишет — вызывает `EstimateCalculator`.
2. Строка в карте `AppServiceProvider::pricingStrategies()`: `TransportType::value => класс`. Классы попадают под тег `pricing.estimate-strategies`, из которого собирается singleton `StrategyDeliveryEstimator`.
3. Параметры в `config/pricing.php`: пределы, ставки, скорость, надбавки, время на операции.
4. Тесты: контрактный `StrategyContractTest`, проверки пределов, функциональный тест маршрута.

Если типа нет в домене, сначала добавляется значение `TransportType`. Вызывающий код не меняется: контроллер, операция и компонент выбора работают с интерфейсом и набором стратегий.

## Границы этапа

- Расстояние приходит в запросе; зоны обслуживания и провайдер расстояний — этап M3.
- Расчёт ничего не сохраняет: записи в БД нет, заказ не создаётся.
- `declared_value` и `dimensions` входят во входные данные, но в цене этапа не участвуют.
- Валюта расчёта задана конфигурацией (`RUB`); несколько валют не поддерживаются.
