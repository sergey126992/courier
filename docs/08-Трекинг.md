# Трекинг

Этап M6: приём геоточек, последние позиции, heartbeat, чтение трекинга с остатком ETA и публичная подписанная ссылка. Требования — в [ЧТЗ - Диспетчеризация и трекинг](<../.github/docs/Техническое задание/Диспетчеризация и трекинг/ЧТЗ - Диспетчеризация и трекинг.md>).
Смены и назначения — в [07-Диспетчеризация.md](07-Диспетчеризация.md), таблицы — в [02-Схема-данных.md](02-Схема-данных.md), решение по ссылкам — в [ADR-0007](adr/ADR-0007-публичный-трекинг.md).

## Маршруты

| Метод | Путь | Кто | Назначение | Коды |
|---|---|---|---|---|
| POST | `/api/v1/assignments/{assignment}/points` | курьер | геоточка по своему назначению | 202, 401, 403, 404, 409, 422, 429 |
| POST | `/api/v1/courier/location` | курьер | heartbeat позиции курьера | 202, 401, 403, 409, 422, 429 |
| GET | `/api/v1/orders/{order}/tracking` | владелец, диспетчер | трекинг заказа | 200, 401, 403, 404, 422 |
| GET | `/api/v1/orders/{order}/tracking-link` | владелец, диспетчер | создание публичной ссылки | 200, 401, 403, 404, 429 |
| GET | `/api/v1/tracking/{code}` | гость с подписью | публичный трекинг | 200, 403, 404, 429 |

Публичный трекинг — единственный маршрут без токена; его защищают подпись ссылки (`signed`) и лимит по IP.

## Приём геоточки

`POST /api/v1/assignments/{assignment}/points` — набор полей закрыт, лишние ключи отклоняются:

| Поле | Обязательность | Правила |
|---|---|---|
| `latitude` | обязательно | от −90 до 90, не больше шести знаков после запятой |
| `longitude` | обязательно | от −180 до 180, не больше шести знаков после запятой |
| `recorded_at` | необязательно | момент времени; без него берётся текущее время приложения |

Ответ 202 — точка принята, пересчёт трекинга выполняется при чтении:

```json
{ "data": { "accepted": true, "recorded_at": "2026-11-04T20:31:00+03:00" } }
```

Правила приёма:

| Правило | Поведение |
|---|---|
| Владение | точка принимается только по своему назначению; чужое и несуществующее — 404, другая роль — 403 |
| Статус назначения | допустимы только «принято» и «забрано»; иначе 409 `ASSIGNMENT_NOT_ACTIVE` |
| Порядок времени | время точки должно быть строго больше времени предыдущей точки этого назначения; иначе 422 `TRACKING_POINT_OUT_OF_SEQUENCE`, поле `recorded_at` |
| Допуск будущего | время в будущем допускается не дальше `tracking.point_future_tolerance_minutes` (`TRACKING_POINT_FUTURE_TOLERANCE_MINUTES`, по умолчанию 5 мин); нарушение — 422 `VALIDATION_FAILED`, поле `recorded_at` |
| Неизменяемость | таблица только для добавления: модель запрещает изменение и удаление сохранённой точки |
| Согласованность | назначение блокируется на время транзакции, точка и последние позиции пишутся вместе |
| События | приём точки событий не пишет |
Источник точки — только `courier`; набор расширяется миграцией.

## Последняя позиция и heartbeat

Хранятся две независимые записи:

| Таблица | Ключ | Что обновляет |
|---|---|---|
| `assignment_last_positions` | одно назначение — одна строка | геоточка назначения |
| `courier_last_positions` | один курьер — одна строка | геоточка назначения и heartbeat |

Обе записи обновляются `upsert` по уникальному ключу: число строк не растёт, дубликатов нет.
Позиция курьера живёт отдельно от позиции назначения — её использует подбор кандидатов ([07-Диспетчеризация.md](07-Диспетчеризация.md)).

`POST /api/v1/courier/location` — heartbeat:

| Поле | Обязательность | Правила |
|---|---|---|
| `latitude`, `longitude` | обязательно | те же, что у геоточки |
| `recorded_at` | необязательно | по умолчанию текущее время |

Heartbeat допустим при открытой смене независимо от активного назначения; без смены — 409 `COURIER_SHIFT_NOT_OPEN`.
Обновляется только последняя позиция курьера; ответ 202 с `accepted` и `recorded_at` — тот же контракт, что у геоточки.

## Чтение трекинга заказа

`GET /api/v1/orders/{order}/tracking` — владельцу заказа и диспетчеру. Курьер и администратор получают 403, чужой заказ неотличим от несуществующего (404).

| Параметр | Правила |
|---|---|
| `limit` | 1–200, по умолчанию 50 — размер страницы ленты геоточек |
| `cursor` | курсор предыдущей страницы |

Лента берётся по активному назначению, без него — по последней попытке, поэтому история доступна после вручения, неудачи и отмены.
Порядок — время и идентификатор: дублей и пропусков между страницами нет; связи загружаются заранее.

```json
{
  "data": {
    "order": {
      "number": "CRG-2026-000123",
      "status": "picked_up",
      "status_label": "Забран"
    },
    "eta_minutes": 22,
    "eta_at": "2026-11-04T20:37:00+03:00",
    "remaining_eta_minutes": 9,
    "eta_source": "computed",
    "last_position": {
      "latitude": 55.760120,
      "longitude": 37.618400,
      "recorded_at": "2026-11-04T20:31:00+03:00"
    },
    "courier": {
      "name": "Иван К.",
      "transport": "light",
      "light_vehicle_kind": "bicycle"
    },
    "points": [
      {
        "latitude": 55.760120,
        "longitude": 37.618400,
        "recorded_at": "2026-11-04T20:31:00+03:00",
        "source": "courier"
      }
    ],
    "pagination": {
      "per_page": 50,
      "has_more": false,
      "next": null,
      "prev": null
    }
  }
}
```

`eta_minutes` и `eta_at` — зафиксированный при создании заказа прогноз (время заявки плюс прогноз); он не пересчитывается.

### Остаток ETA и признак источника

Расчёт: расстояние от последней позиции до адреса доставки делится на скорость транспорта с учётом часа пик плюс время обработки, результат округляется вверх до минуты; при нулевой скорости остаток не считается.
Остаток отдаётся как `planned` (`eta_source = planned`), если нет последней позиции или активного назначения (вручено, не выполнено, отменено), у адреса нет координат или провайдер расстояний недоступен. Сбой провайдера не меняет код ответа, причина клиенту не раскрывается.
| `eta_source` | Смысл | Когда |
|---|---|---|
| `computed` | остаток посчитан по последней позиции и текущим условиям | присутствует |
| `planned` | остаток не вычислялся | отсутствует в ответе |

## Публичная ссылка

Ссылка подписана (`URL::temporarySignedRoute`, маршрут `tracking.public`) и нигде не хранится: код и срок закодированы в ней, проверяет слой `signed`; таблиц и уборки просроченных строк нет.
Срок — `tracking.link_ttl_hours` (`TRACKING_LINK_TTL_HOURS`, по умолчанию 168 часов); повторный запрос выдаёт новую ссылку, отозвать ранее выданную нельзя.

```json
{ "data": { "url": "http://127.0.0.1:8080/api/v1/tracking/trk_cd96ad16ef547f62?expires=1780000000&signature=...", "expires_at": "2026-11-11T20:20:00+03:00" } }
```

## Публичный ответ

`GET /api/v1/tracking/{code}` — без токена, с подписью и лимитом по IP (60 запросов в минуту).

```json
{ "data": { "status": "picked_up", "status_label": "Забран", "eta_minutes": 22, "eta_at": "2026-11-04T20:37:00+03:00", "district": "Северный", "updated_at": "2026-11-04T20:31:00+03:00" } }
```

Состав ответа — только белый список полей; ресурс ничего не добавляет:

| Поле | Содержание |
|---|---|
| `status`, `status_label` | код и подпись статуса заказа |
| `eta_minutes`, `eta_at` | зафиксированный прогноз и его момент |
| `district` | район адреса доставки без улицы и дома; `null`, если район не задан |
| `updated_at` | время последнего изменения заказа |

В публичный ответ не попадают адрес, улица, дом, координаты, имя, телефон, цена, номер заказа и сам код трекинга.

| Код | Когда |
|---|---|
| 403 `INVALID_SIGNATURE` | подпись отсутствует, подделана или срок истёк — до обращения к данным |
| 404 `NOT_FOUND` | код трекинга не существует; ответ неотличим от прочих 404 |
| 429 `RATE_LIMITED` | превышен лимит по IP, в ответе `Retry-After` |

### Кэш и его инвалидация

Ключ — `tracking:public:{code}`; статус в ключ не входит, иначе для его чтения нужен запрос к базе.
Срок — `tracking.public_cache_seconds` (`TRACKING_PUBLIC_CACHE_SECONDS`, по умолчанию 10 секунд) с разбросом `tracking.public_cache_jitter_ratio` (±20 %).
Смена статуса сбрасывает ключ: слушатель `DeliveryOrder::updated` удаляет его при изменении `status`.
Исключение загрузчика не кэшируется: несуществующий код каждый раз даёт 404.

## Права

| Действие | Курьер | Диспетчер | Отправитель | Администратор | Гость |
|---|---|---|---|---|---|
| Геоточка по назначению | своё | 403 | 403 | 403 | 401 |
| Heartbeat | да | 403 | 403 | 403 | 401 |
| Чтение трекинга заказа | 403 | любой заказ | свой заказ | 403 | 401 |
| Создание публичной ссылки | 403 | любой заказ | свой заказ | 403 | 401 |
| Публичный трекинг | по подписи | по подписи | по подписи | по подписи | по подписи |

## Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `ASSIGNMENT_NOT_ACTIVE` | 409 | точка по назначению вне статусов «принято» и «забрано» |
| `COURIER_SHIFT_NOT_OPEN` | 409 | heartbeat без открытой смены |
| `TRACKING_POINT_OUT_OF_SEQUENCE` | 422 | время точки не больше времени предыдущей точки назначения |
| `VALIDATION_FAILED` | 422 | формат и диапазоны координат, лишние поля, время в будущем сверх допуска |
| `INVALID_SIGNATURE` | 403 | подпись публичной ссылки отсутствует, подделана или просрочена |
| `NOT_FOUND` | 404 | чужой заказ, чужое назначение или несуществующий код трекинга |
| `FORBIDDEN` | 403 | роль без права на операцию |
| `RATE_LIMITED` | 429 | превышен лимит частоты |

Тексты пояснений — в `lang/ru/tracking.php` и `lang/ru/errors.php`.

## Лимиты частоты

| Маршрут | Именованный лимит | Ключ | Значение по умолчанию |
|---|---|---|---|
| геоточка назначения | `courier-points` | курьер | 120 запросов в минуту |
| heartbeat | `courier-heartbeat` | курьер | 120 запросов в минуту |
| создание публичной ссылки | `tracking-link` | пользователь | 10 запросов в минуту |
| публичный трекинг | `tracking-public` | IP | 60 запросов в минуту |

Значения читаются из `config/rate_limits.php` (`RATE_LIMIT_COURIER_POINTS_*`, `RATE_LIMIT_COURIER_HEARTBEAT_*`, `RATE_LIMIT_TRACKING_LINK_*`, `RATE_LIMIT_TRACKING_PUBLIC_*`). Чтение трекинга заказа лимитом не ограничено.
