# Интерфейс

Реализация M9 «Кабинет и панель диспетчера» и M12 «Экран настроек уведомлений»: экраны и доступы, стек, токены и темы, компоненты, оформление, адаптивность, доступность, проверки. Требования — в [ЧТЗ - Кабинет и панель диспетчера](<../.github/docs/Техническое задание/Кабинет и панель диспетчера/ЧТЗ - Кабинет и панель диспетчера.md>).
Слои — в [01-Архитектура.md](01-Архитектура.md), вход и роли — в [03-Доступ-и-роли.md](03-Доступ-и-роли.md), решение о серверном интерфейсе — в [ADR-0011](adr/ADR-0011-ssr-интерфейс-blade-livewire.md), тесты — в [14-Тесты.md](14-Тесты.md).

## Стек и структура

Интерфейс серверный: Blade-шаблоны и Livewire 4 отдают готовый HTML, Alpine.js отвечает только за локальное поведение оболочки, Tailwind v4 собирает CSS из токенов. SPA, клиентского роутинга и отдельного слоя состояния нет.

| Путь | Назначение |
|---|---|
| `config/livewire.php` | явная конфигурация Livewire 4: layout полноэкранных компонентов (`components.layouts.app`), путь классов и шаблонов, `smart_wire_keys`, `csp_safe` |
| `config/ui.php` | значения интерфейса: бренд, локаль, тема по умолчанию и cookie, домашние страницы ролей, пагинация, интервалы обновления, имена маршрутов писем и трекинга |
| `lang/ru/ui.php` | подписи, состояния, действия и форматы дат интерфейса |
| `resources/css/tokens.css` | единственное место литеральных цветов; роли акцента, действия, нейтрала, состояний, фокуса, `--radius` |
| `resources/css/app.css` | импорт Tailwind и токенов, `@theme inline` с алиасами `--color-*`; палитра Tailwind отключена |
| `resources/css/components/*.css` | восемь файлов в `@layer components`: `badges`, `buttons`, `cards`, `feedback`, `forms`, `lists`, `modals`, `navigation` |
| `resources/css/preview.css` | стиль preview-эталона; в боевых экранах не используется |
| `resources/views/components/app/*.blade.php` | 24 Blade-компонента библиотеки |
| `resources/views/components/layouts/app.blade.php` | единственный каркас документа: тема, шапка, `main`, футер, Vite |
| `resources/views/livewire/{auth,cabinet,dispatcher,admin,account}/**` | 14 шаблонов Livewire-компонентов |
| `resources/views/{auth,cabinet,dispatcher,tracking,errors}/**`, `home.blade.php`, `account.blade.php` | страницы этапа |
| `resources/js/app.js` | Alpine-компоненты оболочки (`themeToggle`, `shellDialog`, `shellDrawer`, вкладки) и запуск Livewire |
| `app/Livewire/**` | 14 классов: `Auth` (4), `Cabinet` (5), `Dispatcher` (2), `Admin` (2), `Account` (1) |
| `app/Services/Order`, `app/Services/Dispatch` | query-объекты `OrderListQuery`, `DispatcherQueueQuery` и `IdempotencyStore`, общие с API |
| `app/Http/Requests/**` | общие классы правил `OrderPayloadRules`, `OrderFilterRules`, `EstimatePayloadRules` |

Livewire берёт тот же Alpine из `resources/js/app.js`: второй не создаётся, `@livewireScriptConfig` в layout отключает автоподключение. Значения — только через `config('ui.*')`, тексты — через `lang/ru`; литералов и `env()` в шаблонах нет.

## Карта интерфейса

| Экран | Маршрут (имя) | Кто видит | Условия доступа |
|---|---|---|---|
| Лендинг | `GET /` (`home`) | гость | авторизованный получает редирект на домашнюю страницу роли |
| Вход | `GET /login` (`login`), `POST /login` (`login.store`) | гость | после входа — запрошенный адрес или домашняя страница роли |
| Регистрация | `GET /register` (`register`), `POST /register` (`register.store`) | гость | `throttle:auth-register` |
| Запрос сброса пароля | `GET /forgot-password` (`password.request`), `POST` (`password.email`) | гость | `throttle:auth-password-forgot`; ответ не раскрывает существование аккаунта |
| Сброс пароля | `GET/POST /reset-password/{token}` (`password.reset`) | гость | `signed` |
| Напоминание о подтверждении | `GET /email/verify` (`verification.notice`), `POST` (`verification.send`) | авторизованный | `throttle:auth-email-resend` |
| Подтверждение почты по ссылке | `GET /email/verify/{id}/{hash}` (`verification.verify.web`) | любой, у кого есть подпись | `signed`, без `auth`: ссылку можно открыть в другом браузере |
| Профиль | `GET /account` (`account`), `POST /account` (`account.update`) | авторизованный | правка полей — по `UserPolicy` через `UpdateProfileRequest` |
| Сервис оповещений | `GET /notifications/service` (`notifications.service`), `POST /notifications/service/dlq/{id}/replay` (`notifications.service.dlq.replay`) | администратор | `verified`, `can:notifications:manage`; диспетчер и остальные роли получают отказ; данные — служебный API сервиса и `/metrics` | `verified`; данные читает Livewire через служебный API сервиса, база монолита не используется; вход — карточка-ссылка в профиле |
| Выход | `POST /logout` (`logout`) | авторизованный | завершает веб-сессию |
| Список заказов | `GET /cabinet/orders` (`cabinet.orders`) | отправитель | `verified`, `can:create` |
| Создание заказа | `GET /cabinet/orders/create` (`cabinet.orders.create`) | отправитель | `verified`, `can:create` |
| Карточка заказа | `GET /cabinet/orders/{order}` (`cabinet.orders.show`) | владелец, диспетчер | `verified`, `can:viewAny`; чужой заказ отправителя — 404, роль без доступа — 403 |
| Трекинг заказа | `GET /cabinet/orders/{order}/tracking` (`cabinet.orders.tracking`) | владелец, диспетчер | `verified`, `can:viewAny`; чужой заказ — 404 |
| Очередь диспетчера | `GET /dispatcher` (`dispatcher.queue`) | диспетчер | `verified`, `can:assign` |
| Карточка диспетчера | `GET /dispatcher/orders/{order}` (`dispatcher.orders.show`) | диспетчер | `verified`, `can:viewCandidates` |
| Публичный трекинг | `GET /tracking/{code}` (`tracking.public.web`) | получатель по ссылке | `signed`, `throttle:tracking-public`, без `auth` и `verified` |
| Страницы ошибок | 403, 404, 419, 429, 500 | все | HTML-страницы `resources/views/errors/*`; `ProblemRenderer` вне `api/*` JSON не формирует |
| Preview-эталон | `GET /preview`, `GET /preview/{demo}` (`preview.index`, `preview.demo`) | разработчик | только при `APP_ENV=local` и `PREVIEW_ENABLED=true`, иначе 404 |

| Роль | Экраны | Примечание |
|---|---|---|
| Гость | лендинг, вход, регистрация, восстановление пароля, подтверждение почты, публичный трекинг по подписанной ссылке | на закрытые разделы — 302 на `/login` |
| Отправитель | кабинет: список, создание, карточка, трекинг; профиль | создаёт и отменяет только свои заказы |
| Диспетчер | очередь, карточка диспетчера, профиль | карточка и трекинг кабинета доступны политикой `viewAny`/`view`, но в навигации не показываются |
| Курьер | профиль | кабинет и панель дают 403 |
| Администратор | профиль | кабинет и панель дают 403; форма правки профиля не выводится |

Меню шапки по правам: «Мои заказы» и «Новый заказ» — при `can('create', DeliveryOrder::class)`, «Очередь заказов» — при `can('assign', Assignment::class)`, «Профиль» — всегда авторизованному, гостю — «Войти» и «Зарегистрироваться». Домашняя страница роли — `config('ui.roles.*.home')`.

## Токены и темы

Тема — атрибут `data-theme` на `<html>` (`light`/`dark`). Сервер ставит значение из cookie `ui_theme` (`config('ui.theme.cookie')`); без cookie или при «как в системе» скрипт в `<head>` разрешает `prefers-color-scheme` до отрисовки. Переключатель хранит выбор в cookie и `localStorage`, выставляя `light`/`dark`.

| Роль токенов | Светлая | Тёмная | Где применяется |
|---|---|---|---|
| Акцент (`--token-accent`, `--token-accent-strong`, `--token-accent-soft`, `--token-on-accent`) | `#c2410c` | `#f97316` | активный пункт навигации, подчёркивание вкладки, маркер выбранной строки |
| Основное действие (`--token-action-fill`, `--token-action-text`, `--token-action-fill-hover`, `--token-action-fill-muted`) | `#9a3412`, текст `#ffffff`, hover `#7c2d12`, недоступно `#78716c` | `#c2410c`, текст `#ffffff`, hover `#9a3412`, недоступно `#57534e` | `.btn-primary` |
| Нейтральная заливка (`--token-neutral-fill`, `--token-neutral-fill-hover`) | `#e4e4e7`, hover `#d4d4d8` | `#27272a`, hover `#3f3f46` | `.btn-secondary`, заглушки `skeleton` |
| Поверхности (`--token-canvas`, `--token-surface`, `--token-surface-raised`) | `#f4f4f5`, `#ffffff`, `#fafafa` | `#09090b`, `#18181b`, `#1f1f23` | фон страницы, карточки, поля |
| Границы (`--token-border`, `--token-border-control`) | `#e4e4e7`, `#82828b` | `#27272a`, `#71717a` | разделители; границы полей и вторичных кнопок |
| Состояния (`--token-success`, `--token-warning`, `--token-error`, `--token-info` и мягкие фоны) | `#15803d`, `#854d0e`, `#b91c1c`, `#1d4ed8` | `#4ade80`, `#fbbf24`, `#f87171`, `#60a5fa` | текст сообщений и бейджей |
| Геометрия (`--radius`, `--radius-pill`) | `0.625rem`, `999px` | то же | скругление полей, кнопок, карточек |

Контрасты проверены по WCAG 2.x и закреплены guard-тестом `tests/Arch/UiThemeGuardTest.php`:

| Пара | Светлая | Тёмная | Порог |
|---|---|---|---|
| Текст основного действия на заливке | 7.31 | 5.18 | ≥ 4.5 |
| Текст на приглушённой заливке действия | 4.80 | 7.63 | ≥ 4.5 |
| Текст на нейтральной заливке вторичной кнопки | 13.96 | 14.27 | ≥ 4.5 |

`resources/css/app.css` объявляет `--color-*: initial` и заводит утилиты поверх `var(--token-*): `bg-surface`, `text-action-text` и подобные меняются с темой. Палитровые утилиты Tailwind не генерируются; исключение — `white` и `black` для `welcome.blade.php`. Литеральные цвета (#hex, `rgb()`, `hsl()`, `oklch()`) — только в `tokens.css` и preview (`preview.css`, `views/preview/**`).

## Экран настроек уведомлений (M12)

`/account/notifications` — экран кабинета (`resources/views/account/notifications.blade.php`), целиком отдаётся `account.notification-preferences` (`App\Livewire\Account\NotificationPreferences`). Браузер сервис не вызывает: данные читает и сохраняет `App\Services\Notifications\NotificationPreferencesScreen` через служебный клиент.

| Блок | Состав | Источник |
|---|---|---|
| Матрица «тип события × каналы» | карточка на тип события, внутри — `checkbox` на каждый канал домена | ответ сервиса: строки, доступные роли пользователя |
| Тихие часы | переключатель, два поля `time` и `select` таймзоны | сохранённая строка предпочтения или дефолт |
| Привязка Telegram | `status-badge` со статусом, момент подтверждения, ссылка deep-link со сроком, кнопки «Привязать», «Обновить», «Отвязать» | `GET /api/v1/channel-bindings` и `POST /api/v1/channel-bindings/telegram/start` |
| Результат действия | `<x-app.alert>` в области `aria-live` | ответ Livewire-действия |
| Недоступность сервиса | `<x-app.alert variant="error">` с кнопкой «Обновить», форма скрыта | ошибка служебного вызова |

Правила экрана: матрица — карточки в `md:grid-cols-2` (на 360–390 px один столбец без прокрутки); курьеру сервис возвращает только его типы событий, диспетчеру и администратору — пустой набор с пояснением, блоки тихих часов и привязки остаются; критичный тип — с подсказкой, что email не отключается; `chat_id`, адрес сервиса и токен в разметку и свойства компонента не попадают (allowlist клиента, проверяют тесты); сохранение, выпуск ссылки, отвязка и обновление статуса — через `aria-live`, ошибки полей — `@error` у `field`; общие токены, обе темы, без литеральных цветов и `overflow-*`.

## Страница «Сервис оповещений» (M13)

`GET /notifications/service` — админ-страница (`resources/views/admin/notifications/service.blade.php`), целиком отдаётся `admin.notification-service-page` (`App\Livewire\Admin\NotificationServicePage`). Доступ — gate `notifications:manage`; прочим ролям страница и прокси-повтор недоступны. Данные читают `App\Services\Notifications\NotificationDlqJournal` и `NotificationServiceClient`.

| Блок | Состав | Источник |
|---|---|---|
| Вкладка «DLQ» | фильтры `select` по каналу и состоянию, кнопки «Применить» и «Обновить», список строк на `x-app.notification-row` с кнопкой «Повторить» у открытой записи, «Показать ещё» для следующей порции | `GET /api/v1/dlq` сервиса |
| Пустая очередь | `x-app.empty-state` с причиной и подсказкой | ответ сервиса без строк |
| Недоступность сервиса | `x-app.alert variant="error"` с кнопкой «Обновить» | исключение служебного вызова |
| Вкладка «Метрики» | счётчики по каналам, глубина DLQ по состояниям, лаг и pending по потокам, возраст Outbox сервиса и монолита на `x-app.data-list`; кнопка «Обновить» | `GET /metrics` сервиса; возраст Outbox монолита — `outbox_messages` |
| Результат повтора | `x-app.alert` в области `aria-live`; тон — успех, предупреждение или ошибка по коду ответа | ответ прокси-повтора |

Правила страницы: вкладки — `x-app.tabs` (`role="tablist"`/`role="tab"`, `aria-selected`, стрелки, Home/End), панели — `aria-labelledby`; DLQ — `x-app.scroll-area` без горизонтальной прокрутки; метрики — `x-app.data-list` (строки и карточки на `48rem`); количество строк — `role="status"` с `aria-live="polite"`; повтор — как из консоли: `POST /notifications/service/dlq/{id}/replay` отдаёт `202`/`404`/`409`, недоступность — `503` без текста исключения; email, телефон, токен и `chat_id` в разметку не попадают; строка DLQ содержит идентификаторы записи и уведомления, канал, состояние, тип события, код причины, число попыток и повторов, время отказа; переключателей транспорта, провайдера push и режимов нет; ошибка метрик — отдельное предупреждение, DLQ остаётся; пустой снимок — `empty-state`.

## Правила оформления

Цвета, тени и радиусы — только токены `resources/css/tokens.css`; литералы в компонентных CSS и Blade запрещены guard-тестом. Прокрутка — только `<x-app.scroll-area>`, `overflow-*` в шаблонах нет (исключение — `overflow-y-auto` внутри компонента). Статус — текстом: `status-badge` выводит `OrderStatus::label()` для заказов и подпись для привязки (`pending`, `verified`, `revoked`), цвет — дополнение; бейдж без подписи не рендерится. Один акцент действия и один навигации на экран: основное — `--token-action-fill`, второстепенные — нейтральные, акцент у активного пункта меню и выбранной строки (`inset 3px 0 0 var(--token-accent)`, фон нейтральный). Длинные значения — `.list-value` с многоточием и полным текстом в `title`. Сообщения не исчезают (`alert`), загрузка с текстом (`spinner`, `aria-busy`), пустое состояние объясняет причину и даёт одно действие. Тексты — из `lang/ru`, параметры — из `config/ui.php`; бизнес-логики в Blade нет.

## Адаптивность

Вёрстка mobile-first на брейкпоинтах Tailwind: `sm` 640 px, `md` 768 px, `lg` 1024 px. До `md` шапка прячет меню и показывает кнопку drawer, от `md` — наоборот. `data-list` показывает одну форму: до `48rem` (768 px) — карточки, от `48rem` — строки. Контейнеры страниц — `max-w-5xl`, формы входа, ошибок и лендинга — `max-w-md`/`max-w-2xl`, двухколоночные `dl` — от `sm`. Drawer — модальный слой: `role="dialog"`, `aria-modal`, Escape, закрытие по подложке, фокус-ловушка и возврат фокуса; список ссылок — `scroll-area`. 

## Доступность

Подпись поля — `<label for>`; `field` выводит `{id}-hint` и `{id}-error`, обязательность — `required`. Ошибка — `aria-invalid="true"` и `aria-describedby` с идентификаторами подсказки и ошибки, текст с `role="alert"`. Фокус — кольцо `2px` цветом `--token-focus` с отступом `2px` у кнопок, ссылок, полей, вкладок и scroll-area. Живые области — количество заказов в очереди (`role="status"`, `aria-live="polite"`), результат копирования ссылки, `toast`. Модальные окна и drawer — фокус-ловушка по Tab, Escape, возврат фокуса, фокус в панели при открытии. Вкладки — `role="tablist"`/`role="tab"`, `aria-selected`, `tabindex` у активной, стрелки влево/вправо, Home и End. Переключатель темы — группа с подписью и `aria-pressed` у значения. `prefers-reduced-motion: reduce` отключает `spinner` и `skeleton` в `feedback.css`. Зона нажатия: `.btn` без `btn-sm`, `.field-control`, флажок (`checkbox min-h-11`, 44 px) — не меньше `2.75rem`; `.btn-sm` и переключатель темы — только второстепенные действия шапки.

## Как запускать и проверять

Ассеты собираются в образе: слой `assets` в `Dockerfile` выполняет `npm ci && npm run build`, поэтому после правок Blade, CSS или `resources/js` нужна пересборка (`make up` / `docker compose build app`). То же делает CI на Node 22.

```sh
make up make test make lint make stan docker compose run --rm app php artisan test docker compose run --rm app ./vendor/bin/pint --test docker compose run --rm app ./vendor/bin/phpstan analyse
```

Уровни тестов интерфейса и их файлы — в [14-Тесты.md](14-Тесты.md). Preview-эталон — `/preview/app-style`, доступен только при `APP_ENV=local` и `PREVIEW_ENABLED=true`: в остальных окружениях маршруты `preview.*` отдают 404. Каталог demo — `resources/views/preview/demos/app-style`, варианты — `variants/variant-1…3.blade.php`; согласован вариант 1 «Акцент на действии». У эталона свой `resources/css/preview.css`; боевые экраны используют только `tokens.css` и `resources/css/components/*.css`.
