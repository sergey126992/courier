# Документация API

Спецификация строится из кода и лежит в репозитории как артефакт:

| Файл | Что это | Кто меняет |
|---|---|---|
| `openapi.json` | OpenAPI 3.1 из маршрутов, FormRequest и API Resource | только команда `api:docs` |
| `README.md` | инструкция | вручную |
| `courier.http` | коллекция ручных запросов для REST Client и демонстрационный блок | вручную |

## Как собрать

```sh
make docs                 # docker compose exec app php artisan api:docs
php artisan api:docs      # внутри контейнера
```

Команда перегенерирует `docs/api/openapi.json` и печатает число путей и схем. Код 1 — генератор завершился ошибкой или файл не читается как JSON.

**Править `openapi.json` руками нельзя**: правку затрёт следующая сборка, а CI покажет расхождение. Источник данных — маршрут, правило FormRequest, поля API Resource или `config/scramble.php`.

## Как проверить

```sh
make docs-check                      # php artisan api:docs --check
php artisan api:docs --check --path=build/openapi.json
```

Проверка собирает описание во временный файл и сравнивает с зафиксированным: расхождение — код 1 и «Описание API устарело». Шаг «Документация API» в `.github/workflows/ci.yml` (в корне репозитория) делает сборку красной при устаревшем артефакте.

При намеренном изменении контракта: изменить код → `make docs` → зафиксировать обновлённый `openapi.json` с остальными изменениями.

## Как посмотреть

Страница документации: `http://127.0.0.1:8080/docs/api` (сырой документ — `/docs/api.json`).

- Страница есть только при `APP_ENV=local` и `APP_ENV=testing`: вне их маршрут не регистрируется (404).
- Доступ проверяет гейт `viewApiDocs`: в локальной среде и тестах открыт всем, в остальных запрещает.
- Токен не нужен: страница показывает контракт, но не даёт прав.

## Что попадает в описание

| Элемент | Источник |
|---|---|
| Пути и методы | `routes/api.php` под префиксом `api/v1` |
| Тело запроса и его правила | FormRequest каждого маршрута (`app/Http/Requests`) |
| Поля ответа | API Resource (`app/Http/Resources`) по типу возврата контроллера |
| Bearer-защита | middleware `auth:sanctum`; публичные маршруты помечены `security: []` |
| Ошибки 401, 403, 404, 409, 422, 429 | единый компонент `ProblemDetails` (RFC 9457, `application/problem+json`) |
| Ответы 401/404/409/422/429 | добавляются по фактам маршрута: защита, параметры пути, тело запроса, ключ повтора, лимит частоты |
| `Idempotency-Key` | middleware `idempotency`: заголовок обязателен у `POST /api/v1/orders` |
| Статусы 201 у создания | атрибут `#[Response(201)]` на методе создания |

Ограничение: ответы из `ApiResponse::json()` (списки с `pagination`, блоки `assignment + order`) описываются как объект без детализации полей. Ресурсы, возвращаемые напрямую (`OrderResource`, `ZoneResource`, `AssignmentResource` и другие), описываются полностью — их тип единственный источник схемы.

## Возможные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `Cannot infer the resource model` | у ресурса нет `@mixin` с моделью | добавить `@mixin \App\Models\...` в PHPDoc класса ресурса |
| `Описание API устарело` | контракт изменён, артефакт нет | выполнить `make docs` |
| `/docs/api` отдаёт 404 | `APP_ENV` не `local` и не `testing` | это ожидаемое поведение |
| `/docs/api` отдаёт 403 | гейт `viewApiDocs` закрыт | проверить окружение приложения |
