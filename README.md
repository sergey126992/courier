# Курьерская служба

Приложение городской курьерской службы: отправители, курьеры, диспетчеры и администраторы, заявки на доставку в пределах одного города.

Сервис закрывает путь заказа целиком — от регистрации до вручения, публичного трекинга и отчёта, — а уведомления вынесены в отдельное приложение.

- регистрация с подтверждением почты, вход по токенам и в браузере, роли и политики;
- расчёт цены и прогноза по трём типам транспорта, зоны обслуживания и провайдер расстояний с кэшем;
- заказ: идемпотентное создание, отмена, список и карточка с историей статусов;
- диспетчеризация: смены, подбор по трём правилам, назначение и действия курьера;
- трекинг с публичной подписанной ссылкой и уведомления по email, push и в Telegram;
- отчёт по заказам с оптимизацией индексов, кабинет и очередь диспетчера в браузере;
- описание OpenAPI из кода с проверкой в CI, демонстрационный набор и сервис оповещений.

## Быстрый запуск

```sh
make up
make fresh     # схема и демонстрационные данные: 12 учётных записей, 8 зон, 20 заказов
make demo      # таблица учётных записей и ключевые номера
```

Показ функционала — в [Демо-сценарий](docs/13-Демо-сценарий.md), данные и учётные записи — в [Демо-данные](docs/12-Демо-данные.md). Описание API — на `http://127.0.0.1:8080/docs/api`.

## Требования

На хосте нужен только Docker.

- Docker Desktop (Windows, macOS) или Docker Engine с плагином `docker compose`;
- свободные порты `8080`, `8025`, `1025`, `5432`;
- `make` для коротких команд; сами команды продублированы ниже.

PHP, Composer и Node на машине не нужны: зависимости и ассеты собираются внутри образов.

## Запуск

Из корня репозитория:

```sh
cd courier
make up
make fresh
```

``.env` и `APP_KEY` создаются автоматически при первом старте контейнера: если файла нет, entrypoint копирует его из `.env.example`, если ключ пустой — выполняет `key:generate`. Инициализация идёт под общим локом в `storage/framework`, поэтому `app`, `queue` и `scheduler` не мешают друг другу, а повторный запуск ничего не перезаписывает. Миграции автоматически не выполняются: до `make fresh` база пустая — эта команда пересоздаёт схему и наливает демо-данные.

Без `make` (например, в Windows без Make) те же шаги напрямую:

```sh
cd courier
docker compose up -d --build
docker compose exec app php artisan migrate:fresh --seed
```

Если переменные нужно изменить до первого старта, скопируйте образец — `cp .env.example .env` (в PowerShell `Copy-Item .env.example .env`): контейнер увидит готовый файл и только сгенерирует ключ.

Первая сборка занимает несколько минут: образ PHP, зависимости Composer, фронтенд-ассеты.

Проверка: приложение отвечает на `http://127.0.0.1:8080/up` кодом 200 и текстом `Application up`.

## Повседневные команды

| Команда | Что делает |
|---|---|
| `make up` | собирает образ и поднимает сервисы |
| `make down` | останавливает и удаляет контейнеры |
| `make test` | все тесты (Unit, Feature, Arch) на PostgreSQL |
| `make test-parallel` | то же в параллельном режиме, как в CI |
| `make lint` | стиль без исправлений |
| `make fix` | автоисправление стиля |
| `make stan` | PHPStan |
| `make fresh` | пересоздаёт базы и наливает демо-данные |
| `make docs` | описание API из кода в `docs/api/openapi.json` |
| `make docs-check` | сверка описания API с кодом |
| `make demo` | показывает демо-учётные записи и ключевые данные |
| `make ps` | состояние сервисов |
| `make logs` | логи всех сервисов |
| `make shell` | оболочка в контейнере приложения |

Сервис оповещений и опциональный брокер:

```sh
docker compose up -d notifications-app notifications-worker notifications-scheduler
docker compose exec -T notifications-app php artisan notifications:dlq-list --state=open --json
docker compose exec -T notifications-app php artisan notifications:metrics-snapshot --refresh --json
docker compose exec -T notifications-app php artisan notifications:broker-health --json
docker compose --profile broker up -d rabbitmq   # без профиля всё работает на Redis
```

- профили compose: `broker` (`rabbitmq` с management UI) и `telegram` (бот); для основного запуска не нужны;
- образы ставят расширение `sockets`: без него `php-amqplib` v3 не подключается к брокеру;
- реальный push: `NOTIFICATIONS_PUSH_PROVIDER=fcm`, `FCM_PROJECT_ID`, `FCM_CREDENTIALS_PATH`; по умолчанию провайдер `fake`, креды не нужны;
- брокер: подключение — `RABBITMQ_*`, переключение — `EVENTS_TRANSPORT=rabbitmq` и `NOTIFICATIONS_TRANSPORT=rabbitmq` с перезапуском процессов.

Любую artisan-команду можно выполнить через контейнер: `docker compose exec app php artisan <команда>`.

## Известные ограничения окружения

- **Сервисы работают от `root` (`user: "0:0"` в compose).** Docker Desktop на Windows монтирует каталог проекта как `root:root 755`, поэтому непривилегированный пользователь не может писать в `storage` и `bootstrap/cache`. Образ по умолчанию работает от `app`, слой зависимостей собирает `builder` — компромисс касается только dev-запуска на Windows.
- **Первая сборка долгая.** В образе только production-зависимости; dev-пакеты (Pint, PHPStan, Pest) ставит entrypoint при первом старте в том `vendor` — далее это не повторяется.
- **`vendor`, `storage`, `bootstrap/cache` — именованные тома.** Код монтируется из проекта, зависимости и кэш — в томах Docker; после смены `composer.json` нужен `make up`.
- **На хосте нет PHP.** `php artisan` выполняется только через контейнер (`make shell` или `docker compose exec app ...`).
- **`make` на Windows нет из коробки.** Без него используйте прямые команды `docker compose run --rm app ...`.
- **Порты заняты.** При конфликте `8080`, `8025`, `1025` или `5432` измените публикацию портов в `docker-compose.yml`.
