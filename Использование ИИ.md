# Использование ИИ в проекте

Краткая памятка: как в этом репозитории организована работа с ИИ-агентом, что где лежит и какие правила соблюдаем.

## Как устроено

| Где | Что это |
|---|---|
| `.github/instructions/main.instructions.md` | Постоянные правила разработки: стек, слои, компоненты, тесты, стиль, запреты |
| `.github/agents/` | Роли агентов: оркестратор, поиск по коду, планирование, исполнение, документация, ТЗ, тесты, UI-preview |
| `.github/skills/` | Узкие навыки: фронтенд-качество (`better-*`), документация, планы, тесты, Serena, диагностика |
| `.github/docs/` | Требования: системное ТЗ и ЧТЗ по этапам |
| `.github/components/` | Контракты UI-компонентов (props, состояния, антипаттерны) |
| `.github/plans/` | Планы работ по логическим папкам |

## Базовый цикл работы

1. **Исследование** — сначала документация (`.github/docs`, `.github/components`), затем код (semantic-поиск, LSP).
2. **План** — для больших задач создаётся файл в `.github/plans/<папка>/План - <название>.md`.
3. **Исполнение** — изменения кода делает агент-исполнитель одним логическим срезом за раз, всегда с тестами.
4. **Проверка** — после каждого среза прогоняются тесты, изменённый код просматривается, при ошибках задача возвращается на доработку.
5. **Документация** — после изменения функционала или компонентов обновляются `.github/docs` и `.github/components`.

## Правила, которые соблюдает агент

- Не делает `git commit` — решение о коммите принимает только пользователь.
- Не откатывает и не «чистит» правки пользователя в рабочей копии.
- Не редактирует код без тестов; тесты быстрые, без сетевых вызовов и ожиданий.
- Интерфейс — только из переиспользуемых компонентов, обе темы, адаптивность, доступность.
- Секреты — только в `.env`, `env()` — только в `config/*.php`.

## Полезное

- Нужен результат по шагам и с проверкой — используется агент-оркестратор.
- Нужно понять, где что лежит, — сначала документация в `.github/docs`, потом код.
- Нужно быстро посмотреть экран или дефект — скилл диагностики с браузером и DevTools.
- Нужен план или ТЗ — соответствующий агент создаёт файл в `.github/plans` или `.github/docs/Техническое задание`.
